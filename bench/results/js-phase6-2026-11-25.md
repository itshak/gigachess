Intel Xeon E5-1620 v2 (4 cores/8 threads), Debian aiserver, Node 24.13.0; baseline rebuilt from exact commit, each variant independently built into its real minified ESM entry. ## Isolated experiments

- ep: perft-internal normalization of unreachably generated double-push EP target, using reverse pawn attack geometry. Public EP/FEN semantics and root state unchanged.
- castle: perft-only filter of blocked standard castling paths and direct rook/color bit tests. Normal context and Chess960 behavior unchanged.
- masked: bulk count unpinned ordinary pawns in single check, exact per-pawn fallback for pins or actual EP candidates; applies check mask after double push calculation. 9,933 independently generated chess.js positions (415 checks), both entries, periodic depth-two oracle checks.
- pinbits: retain singleton blocker bits directly, rather than decoding then encoding its square. Uses the existing magic-screened sniper approach; no copied external implementation.
- combined: blocked standard castling plan filter, direct pin bit mask, and cheaper EP normalization with precomputed same-rank adjacent files. This is not the earlier reverse pawn-attack prototype; it avoids extra halfboard arithmetic and lookups.
- kingroles: prepared separate hypothesis to reuse enemy slider role masks from pin analysis for direct king safety probes; compare against combined, not phase 5, if tested.

## Correctness and packaging

All completed isolated variants passed the 114 frozen ordinary/minified standard and Chess960 perft, FEN/EP and state restoration tests. Pinbits and combined also passed independent attack-map parity and the 380 ordered move fixtures. Combined passed npm test, including 1,000 seeded chess.js games, 118,380 plies, 11,684 undos, zero mismatches, plus the independent 9,933-position perft test. npm pack --dry-run --json: 115 files, all ordinary/fast declarations and lazy magic/Zobrist chunks. No new runtime dependencies, no WASM/Rust, no substantive competitor code incorporated, no licensing changes needed. MIT competitor's package declares license but repository checkout has no LICENSE file; obtain explicit copyright notice before any substantive source reuse.

## Next architecture target

If the separate king-target mask reuse experiment is not sufficient, isolate a perft-specific color-separated role representation with explicit move flags and preallocated state rather than continuing to tune the public context. Convert once at the perft root and test against the ordinary Board and independent oracles, including Chess960 and state restoration. Do not copy GPL chessops. Do not declare fastest from a single CPU or selective fixtures.

candidate in the **draft** as the fixed-CPU run showed 12.171 to 17.473 Mnps
(start), 12.893 to 12.702 (Kiwipete), 9.191 to 9.630 (endgame), and 16.927 to

endgame timing varied significantly. Do not treat this as a claim of
zero performance regressions; Kiwipete and gameplay A/B have small negative

was -2.7%, FEN parse/write -1.9%, validated replay +0.6%. These small
differences require confirmation on an independent machine.
The kingroles follow-on passed targeted correctness and improved all four
fixtures once; keep its patch for the next independent run, not runtime code
until full correctness and repeatability are demonstrated.
