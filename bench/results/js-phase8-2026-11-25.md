# Phase 8 — public direct movegen and split-32 sliding attacks

Baseline 861c7db. All measurements on aiserver, Xeon E5-1620 v2,
Node 24.19.0 pinned for benchmarks, shared with other project workloads.
No other processes interrupted. Record both CPU and wall times, rotated
lanes, exact counts. No assertion of universal fastest status.

## Runtime changes retained in the draft

- New direct standard generator preserves existing Q/R/B/N promotion
  ordering, king-to-rook castling encoding, and normal per-piece
  ascending destination order. Chess960, cold tables and unsupported
  positions fall back to the general generator.
- Reuse private synchronous move buffer and return an independent typed
  slice; reentrant calls use a local buffer. Caller-provided zero-copy
  buffers unchanged.
- Split each 64-bit relevant slider occupancy into two 32-bit subsets.
  Deterministically search injective multiplicative hashes independently
  for each half, concatenate indices. No simulated 64-bit multiply;
  no collisions or padding. Exactly 102,400 rook and 5,248 bishop
  entries. Fuse rook/bishop lookups in queen attack function.
- Cold fallback uses eight directional ray masks and nearest blocker
  bit scans. Retain independent original ray walk as correctness oracle.
- Reproducible blobs derive from geometry and independent ray walk;
  byte-for-byte regeneration confirmed. Legacy source blobs retained for
  historical experiments but excluded from published package.
- Bundle gate now checks both actual split-table blobs.

## Independent uncached large-batch benchmark: open deficit

4,000 preconstructed positions, 12 equally rotated warmup rounds,
11 timed rounds, separate engine objects each round and checksummed
results. First run: 45,829 prior GigaChess, 129,395 new, 158,502 npm,
171,251 source positions/s. Repeat: 44,392 prior, 110,656 new,
192,139 npm, 171,827 source. New generator substantially improves the
baseline, but still trails both competitors in this independent batch
workload. No all-workload victory claim.

The paired gameplay A/B over Phase 7: +155.5% and +205.8% legal
generation; FEN -28.3% and +4.9%; replay +8.4% and -14.2%. Paired
perft start -19.7%/+27.1%, Kiwipete -2.1%/+13.1%, endgame
-8.4%/+1.5%, promotion +30.4%/-16.5%. Shared CPU/cache contention
and JIT sensitivity are plausible, not proven causes. Retain as
draft candidate because correctness and main competition improved;
repeat controlled A/B before claiming regression-free release.

## Sliding gate

Split-32 hash alone +25.5% paired queen throughput; fused queen
lookup +50.4% (51.3% CPU-time ratio). The isolated cold+loaded
official pinned-runtime suite passes all 3 gates: cold 4.48x
chessops (threshold 1.5x), loaded 4.17x (threshold 2.4x),
100% parity. Full pinned-runtime broad suite log captured separately.
