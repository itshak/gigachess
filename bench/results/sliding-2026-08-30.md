## Derived metrics

- **MQueens/s** = `iters / (medianMs/1000) / 1e6`
- **BigInt slowdown:** `48.96 / 3.41 = 14.4×` (10M) — **✓ proves 10–60× slower, not hot-path viable** (Scala.js precedent, `tc39/proposal-bigint#117`)
- **B vs A:** `(48.96 - 9.35)/9.35 = +423.5%` (10M) — **✓ exceeds ≥30% gate by 393pp**
- **C vs B:** `(63.02 - 48.96)/48.96 = +28.7%` — rescript stub is even faster than B, but is **TS stub** (no ReScript toolchain yet); language decision deferred per `design.md`

## Decision per spec gate

Spec `specs/purechess-benchmarks` Sliding micro-benchmark SHALL: *B (Black Magic lo/hi) SHALL achieve ≥30% higher MQueens/s than A (chessops HQ) to be declared winner; otherwise HQ remains fallback.*

```
1M:  B (48.71) vs A (9.36) → +420.3% → ✓ PASS (≥30%)
10M: B (48.96) vs A (9.35) → +423.5% → ✓ PASS (≥30%)
Winner: black-magic (plain fixed-shift lo/hi)
```

**Result:** With **REAL chessops HQ** (not synthetic stub — `bench/candidates/hq.mjs` now wraps `chessops` hyperbola which allocates `SquareSet` per call and does `minus64`+`bswap`), **Black Magic wins decisively**. The synthetic stub in the earlier baseline incorrectly made HQ look fast (148 MQueens/s fake hyperbola); the honest HQ is **9.3 MQueens/s**. This is the correct bake-off result per `tasks.md` 4.5.

### Implications for encoding

- **Board encoding:** `{lo,hi}` manual pair **locked** — both HQ and Black Magic use `{lo,hi}`; BigInt ruled out per 14.4× slowdown.
- **Slider algorithm:** **Black Magic (plain fixed-shift)** wins bake-off. Phase 2 SHALL use Black Magic for `purechess` sliding attacks, with per-square `mask/magic/shift` + `bench/magic-tables/*.json` generated via MIT `RecklessMagics` (uniform shift 11 in baseline is already sufficient to win; Phase 2 will replace with per-square shifts for minimal table size without changing winner).
- **ReScript:** `C` stub at 63.02 MQueens/s is **28% faster than B** but is a TS stub mimicking `{lo,hi}` record shape — not yet a true ReScript compile. `design.md` bake-off language decision (TS functional vs ReScript manual) remains open; both use same `{lo,hi}` layout, so spec stays language-neutral. ReScript toolchain will be added before language lock.
